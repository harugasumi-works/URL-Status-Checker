# URL Status Checker 要件定義書

## 1. システム概要

URL Status Checker は、ユーザーが入力した複数のURLへHTTPS GETリクエストを行い、応答状況を一覧表示するデスクトップアプリケーションである。

## 2. 対象範囲

### 対象
- URLの手入力
- URLの一括ステータスチェック
- チェック結果の一覧表示
- 成功／失敗件数の集計
- JSON / CSV形式での保存

### 対象外
- ファイルからのURL一括取込
- HTTP URLのチェック
- リダイレクト先までの追跡

## 3. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | ユーザーはスキームを除いたURLを入力できる。 |
| FR-02 | URL入力後、Enterキーで一覧へ追加できる。 |
| FR-03 | Scan実行時、一覧中の全URLを再チェックする。 |
| FR-04 | 複数URLを並行してチェックする。 |
| FR-05 | 結果をURL、Status、Code、Detailとして一覧表示する。 |
| FR-06 | 応答結果をSuccessまたはFailとして分類する。 |
| FR-07 | 全URLのtotal、successCount、failureCountを集計する。 |
| FR-08 | 最新のスキャン結果をJSONまたはCSVで保存できる。 |
| FR-09 | ネットワークエラー、不正なURL等はFailとして結果に残す。 |

## 4. 結果判定

| 条件 | 判定 |
|---|---|
| HTTPステータス < 400 | Success |
| 400～499 | Fail（クライアントエラー） |
| 500以上 | Fail（サーバーエラー） |
| 応答なし／URL不正／通信エラー | Fail |

## 5. 非機能要件

- ネットワーク処理中もJavaFXの画面操作が固まらないこと。
- 1リクエストあたりのタイムアウトは5秒、接続タイムアウトは10秒とする。
- 1件のURLの失敗によって、他URLのチェックを中止しない。
- 1回のスキャン結果は、そのスキャンで取得した結果のみを保持する。

## 6. 前提・制約

- Java 26を使用する。
- JavaFX 26を使用する。
- URLには自動的に `https://` を付加する。
