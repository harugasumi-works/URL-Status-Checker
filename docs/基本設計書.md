# URL Status Checker 基本設計書

## 1. システム構成

システムは以下の5領域で構成する。

| 領域 | 主な役割 |
|---|---|
| ui | 画面表示、入力、ボタン操作、結果反映 |
| concurrency | URLチェックの並行実行と結果収集 |
| domain | スキャン要求・結果・集計データの保持 |
| net | HTTPSリクエスト生成とHttpClient管理 |
| io | JSON / CSV変換およびファイル保存 |

## 2. 処理方式

```text
ユーザー入力
    ↓
ScanRequest生成
    ↓
Scan実行（複数URLを並行処理）
    ↓
ScanResult
    ↓
ExecutionResult
    ↓
Report集計
    ↓
画面表示 / JSON・CSV保存
```

## 3. 画面設計

### 3.1 メイン画面

上部に操作バー、中央に結果テーブルを配置する。

操作バー：
- Scanボタン
- Saveボタン
- URL入力欄

結果テーブル：
- URL
- Status
- Code
- Detail

### 3.2 Save

Saveは以下を選択できる。
- Export to JSON
- Export to CSV

スキャン結果が存在しない場合、Saveは使用不可とする。

## 4. データ設計

### 4.1 ScanRequest

```text
id
requestedURL
```

### 4.2 ScanResult

```text
id
context(ScanRequest)
outcome(Outcome)
```

### 4.3 Outcome

```text
Success(timeStamp, statusCode, latency)
Fail(timeStamp, statusCode, reason)
```

### 4.4 Report

```text
stats(total, successCount, failureCount)
successes
failures
```

## 5. 主要処理

1. ユーザーがURLを入力する。
2. `ScanRequest`を生成して一覧へ追加する。
3. Scan押下時、一覧の全URLから`ScanRequest`を再構築する。
4. `Operator.scanAll()`で並行実行する。
5. 各URLの結果を画面へ逐次反映する。
6. 全件完了後、`Report.summarize()`で集計する。
7. Save選択時、JSONまたはCSVを生成してファイルへ保存する。
